# 写人话，但先有证据

不要把数据表读成心理分析。主线是展示选择，不等于主人身份。每个“最多”标明比较范围和计数单位；覆盖不完整时说“已读取记录里”，不说“十年来唯一”。消费总额不作主视觉，单件真实实付可用；没有实付就显示未知。

总结按实际日期、商品、已知金额选择4—6个节点；不足就减少。每年小标题≤8字，专题40—100字，证据不足不凑4—6个。主线可以是猫粮、纸尿裤、户外、美妆或混合消费，别给每个人套硬件换代。店名、人设表达必须是轻松的文案设定，不能把猫粮购买直接推成“养猫年轻人”，也不能把纸尿裤订单推成“本人已生育”。愿望组随实际内容调整，不默认“想体验的科技产品”；用户可以改、删、打卡，不自动安排购买预算。

保留 script 生成的商品ID引用。角色彩蛋可以像某位熟悉角色的某个行为，也要指出购买记录无法证明的部分。不给人物贴人格、情绪、心理标签。锐评吐槽物件和下单行为，不羞辱人。

## 三首配乐候选

从买什么、怎么买、反复买什么选歌，不从年份跨度选。每首给歌名、歌手、一句气质匹配判断，以及两条具体日期/商品/商品ID依据；两条不能拿同一条订单凑。歌名须真实存在，不知道就核实，不捏造“某歌是用户常听”。不放歌词。

脚本提供每主线六首、按回购/下单节奏/同单件数/系列顺序/品类组合分类的候选池，豆包应从中挑3首，并用脚本行为事实改写理由，例如“同款6个独立订单、相邻已读间隔中位366天”而非“某日商品属于猫粮”。每首歌的歌名/歌手已在 `song-catalog.json` 记录官方来源；新增曲目须重新核实。只有一条记录时不强配3首。商业歌曲无音频，仅外部搜索跳转；跳转可访问不代表会员曲可播放，不声称已测所有平台。真正网页音轨另用授权清楚的文件，可让用户自己提供。

本包 `music.py` 可以合成一段原创示意器乐，不是在线写歌结果；不得宣传“豆包已经生成店歌”。若要探索豆包音乐功能，先核对当前版本有无入口、下载能力和使用条款；会消耗积分先说明成本，不连续重试。页面发布、音频对外发布和服务开通都不能默认替用户同意。

每首给两条理由，每条一句话；用短名，不复制原始商品长标题，也不在两条结尾重复气质判断。每首至少一条证据在这一组候选中独有，同一证据全文最多出现两次。脚本为每条线索给clue_id，并分配不同的独立订单；记录不足时减少候选并如实说明，不靠换句话反复用同一件商品。
