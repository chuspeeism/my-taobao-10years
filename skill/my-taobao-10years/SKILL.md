# 我的淘宝十年 · 十年小铺

普通用户只要用自然语言提出要求。你负责采集、运行脚本和交付，别把命令甩给用户。支持 Windows 和 Mac；只使用 Python 3.9+ 标准库。模板自包含，无需服务器、API Key 或运行时联网。

## 先说明现在要做什么

简短说清：先读列表、挑出数码产品及配件，再开小铺。这家小铺只放数码。只读本人交易成功订单；登录、扫码和验证码由本人操作；实际能读几年就展示几年。确认当前是用户本人账号，不确定就暂停，不自行换账号。

以本 Skill 所在目录为基准定位 `scripts/shop.py`、`assets/template/`。若安装器只拿到了本文件，应取得**同一仓库的完整 Skill 目录**再继续，不能现场另造模板。不依赖固定用户名、盘符和绝对路径，不要求用户安装 git。已有 Python 直接用：依次试 `py -3 --version`、`python --version`、`python3 --version`，打印出 3.9 以上的版本号才算有；Windows 上 `where python` 能找到的可能只是微软商店占位程序，运行没有输出或退出码 9009 都算没装。缺 Python 要先说明并征得同意再安装，用户不同意就如实说开不了店。新建一个用户可找到的任务文件夹，把私有数据放其下；不把真实数据写进已安装的 Skill。

## 订单只从淘宝现读，没登录就请用户扫码

这次对话里还没读过淘宝订单，第一步就是打开淘宝读列表，哪怕用户只说了“把订单小铺做出来”“用刚安装的 Skill 开店”。**不要去搜这台电脑、云主机或别的设备上的文件找订单**，也不要拿以前留下的 `orders.json` 顶替。只有用户自己说“用这个文件”并给出位置时才改用文件，并如实写明数据来自文件、不是这次从淘宝读的。

1. 用豆包自带的浏览器（对话右边打开的网页）打开淘宝「已买到的宝贝」：`https://buyertrade.taobao.com/trade/itemlist/list_bought_items.htm`。当前在云主机或沙箱里时，先切到用户这台电脑再打开。
2. 页面要登录时就停下，对用户说：“请用手机淘宝扫一下右边页面上的二维码登录，扫好了跟我说一声。”然后结束本轮回复。不替用户输入账号、密码和短信验证码，不换账号。
3. 用户说扫好了，先看当前页面确实是订单列表；页面上的账号拿不准是不是用户本人，就问一句。已经是登录状态也按这条确认。
4. 用户一条消息里既要读订单又要开店，读完列表就接着往下做，不用等下一条消息；只有遇到登录、验证码、滑块才停。列表读完就离开淘宝，不打开订单详情。

## 1. 只读淘宝列表，边读边保存

读取 [references/collection-and-facts.md](references/collection-and-facts.md) 和 [references/data-format.md](references/data-format.md)。以执行当天为终点回溯十年，按北京时间日期整理。真实输入必须在 `coverage.as_of` 写明本次采集日；脚本据此确定十年起止日，排除更早及未来记录，不用脚本运行当天替代采集日。默认**只读取订单列表**，不自动逐单补详情。

优先用 `scripts/taobao-list-extractor.js` 在同一次读取里拿到每单的文字和图片，一遍读完，不要为补图重新翻页。先用相邻两页实证分页、字段和图片归属：页码变化之外，还须确认首末订单ID确实变化；不能只改URL参数就认定翻页。文字和图片须在同一订单容器内以订单ID关联，再逐商品行核对，一单多件保留多图；不能按两个独立数组的下标配对。详见采集规范的“两页试采”。试采不过就先报告具体缺失或失败，不批量重跑整套页面。试采通过后再按年份或可读取窗口保守限速、断点保存，每个窗口记录成功、未读取、失败，不能用几十单外推完整十年。每读完一页看这一页最早的日期，早于十年起点就停止翻页。

交易成功之外的未付款、取消、关闭订单不展示。退款、部分退款和退款中先单列待核；列表看不到退款信息就标注“未逐单核退款”。一单多件分别保存，实付按订单只计一次，不能平摊成商品实付。缺图留空，不能用网图顶替。商品图只用这条订单列表里的对应图片；代表商品按原图核对，别把抠坏的白色机身当原图。

在私有目录保存 `orders.json`、`images/`、`覆盖报告.md`、`采集进度.json`。原订单ID仅供去重和私下核对，不进入网页。不要读取聊天，不做交易、不领券、不注册服务，不保存浏览器配置、登录令牌、地址、手机号、真名或账号名。遇到登录、验证码、滑块或限流，**立即停止浏览器操作并结束本轮回复，等用户本人操作，不绕过**；有遮罩时底层DOM仍可读，不代表页面正常。协助工具返回“完成”也不能当作验证通过。须等用户明确说继续、且当前可见页面的验证遮罩已消失，才能恢复；用户要求“先暂停”时不得交还控制权后自行恢复采集。可以仅整理已保存的本地文件，不再读浏览器。详情读取只有用户另提要求才进行；补详情受阻时可说明情况，用已保存列表继续。

## 2. 脚本先算事实，再写成人话

运行（路径都换成当前机器上的实际绝对路径并加双引号）：

```text
python "<Skill目录>/scripts/shop.py" analyze "<私有目录>/orders.json" "<私有目录>/profile.json"
```

Mac 可用 `python3`，Windows 可用 `py -3`；不要照抄 POSIX shell 写法到 PowerShell。Windows PowerShell 先执行 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`，否则脚本的中文提示会乱码。`orders.json`、`narrative.json` 必须是 UTF-8：不要用 `>`、`Out-File` 或不带编码的 `Set-Content` 写，用 Python 或 `[IO.File]::WriteAllText` 写。

`profile.json` 给出买得最多的数码小类、品牌/颜色商品行数、跨订单回购、同系列购买顺序、各年和月份的订单节奏、证据商品ID、对比度和同款回购次数/间隔、同品类下单节奏、一单件数、系列顺序和按行为分类的六首候选池。只根据明确标注的分类/品牌/颜色统计；未标注不猜，分类不明先保留“未分类”。字段的提取依据见数据格式。品牌与颜色按**商品行**统计，回购按**独立订单**统计；数量另列，不能混称“买得最多”。同系列后买不等于升级、换掉或用过，只有商品代次有明确事实才讨论代次。

这家小铺只放**实体数码产品及配件：手机、电脑及配件、显示器、键盘键帽、耳机音箱、相机影像、存储、游戏机和实体游戏、平板、手表、智能设备等。食品外卖、日用品、服装、书、课程，以及软件、激活码、密钥、账号、会员、兑换码、数字版游戏、远程安装和维修服务都不放**。给每个商品行写 `digital`（是写 true，不是写 false）；数码商品的 `category` 写小类，比如耳机、键帽、游戏卡带。脚本只上架 `digital` 为 true 的行，标题明确是虚拟商品或服务的一律不上架。用户要放别的商品，如实说明这个 Skill 只做数码，不要手动加进去。一件数码商品都没有时脚本会停下，如实告诉用户开不了店，不放别的凑数。

判错最常见的是整批漏掉大件：手机、掌机、主机、显示器被标成 false，整家店就缺了最值钱的东西。所以 **analyze 之后、写 narrative.json 之前，必须看一遍 `profile.not_shown_review`**：这是没上架的商品里最贵的一批，加上标题带数码词的，按实付从高到低排（`paid_basis` 写“整单N行”的，金额是整单的）。其中是实体数码的，回到 `orders.json` 改成 `digital: true`、写好 `category`，重新 analyze；日用品、服装、家具照样不放。看完在 `narrative.json` 写 `"not_shown_reviewed": true`，否则 `build` 不放行。这份名单只留在私有目录。

配色、默认店名和店内音乐跟着这个人买得最多的数码小类变（`profile.line`），专题、代表商品和配乐理由也都来自这个人的数据。成人、健康隐私、政治、灰产、管制、迷信殡葬类即使算数码也默认下架，只记行数，不进网页和 profile。

词表拦不干净，所以**写 narrative.json 前必须逐条看 `profile.spotlight`**：这些商品会出现在首屏盒子、小电脑屏幕、拍立得和人气单品里。不是数码产品或配件的，或者观众录屏发出去会尴尬或出事的（暗示成人、病症隐私、带政治人物名字、破解代办、别人的姓名），就把商品ID写进 `narrative.json` 的 `hide`；看完写 `"spotlight_reviewed": true`，否则 `build` 不放行。隐藏后重新 analyze 看新的 spotlight，再过一遍。

交付时用一句话告诉用户：“这家店放了 N 件数码商品；另有 K 件不适合公开的已下架。”用户明确说“下架的也放上”才加 `--keep-sensitive`。

阅读 [references/copy-and-music.md](references/copy-and-music.md)，先从 `profile.song_pool` 的六首已核实候选中，根据 `behaviors` 挑3首，用具体的回购次数、下单间隔或同单件数写两条理由；每首两条理由、每条一句话，用商品短名；每首至少一条线索在本组中独有，同一线索全组最多用两次，不在两条结尾重复同一句话。不要只复述商品属于什么类，也不要按年份跨度选曲。

根据脚本事实写私有目录的 `narrative.json`：200字内总结、每年短标题和一句话、证据足够时4—6个专题、6—8组问答、有据的愿望建议；语气可为平实/作家/锐评。别把技术口径堆到主文案，读取范围与金额口径放页脚。数据稀少就减少专题，不虚构凑数。

可写影视人物趣味联想：比较3位观众熟悉的角色，用2—3类反复出现的商品行为说明像在哪，给不像和另两位未选原因；证据弱可关闭。它不是人格诊断。镇店之宝是展示选择，不代表最喜欢。建议每条都带商品ID，脚本会检查引用存在；文字事实仍需逐句回查。

配色用脚本已经校验的主题。买得最多的是键盘外设或游戏，或者看不出小类时，严格保留原版：#eceefb背景、#c6f432强调、#7b5cff副色、蓝色电脑；背景大字保持很淡、六色粉彩盒混排、便签浅底、跑马灯醒目，屏幕是径向渐变。手机、影音、影像、电脑这几个小类只改色相，保留相同层次和饱和强调色；会同时传到网页、CSS备用小电脑、3D机身和Canvas屏幕。不要只在 custom.css 改两个颜色就声称全页换色。`profile.contrast` 五组文字对比度均须 ≥4.5；其他装饰保留模板设计。修改文案不能改页面结构和功能脚本。

## 3. 填模板，生成文件夹和单文件

```text
python "<Skill目录>/scripts/shop.py" build "<私有目录>/orders.json" "<交付目录>/我的小铺" --narrative "<私有目录>/narrative.json"
```

输出目录须是新的，避免覆盖旧版本。`build` 复制固定模板、匿名编号后的 `data.js` 与对应图片，产生相邻的 `我的小铺-单文件.html` 和打包检查。`profile.json` 是本地核对资料；交付前同样查隐私。原始 `orders.json` 不复制进网页目录。

商业歌曲只给推荐和“去听”跳转，**不下载、不内嵌商业音频**。可以加入用户有权使用的本地音乐，来源和授权写入 `audio.license`。模板内带7首100秒的授权纯音乐，脚本按买得最多的数码小类选择一首，署名和许可自动带入页脚与单文件。第一次点击页面任意位置或按键请求播放，静音按钮记住选择；不承诺打开即有声。合成器仅作为找不到授权音乐时的手动兜底，不默认使用，更不能称为豆包作曲。见 [references/music-and-chat.md](references/music-and-chat.md)。未取得音频时不显示音乐控制按钮，仅显示歌曲推荐。

`chat.enabled=false` 可以连同导航干净隐藏问答区。默认离线预设/规则回答，无需账号和费用；不会自动把订单发给外部服务。答不了时可显示可手动复制的问题与摘要，再由用户打开豆包粘贴。没有验证过网址能自动带资料，不能宣传一键接入；不自行发布页面、开通云服务或填写密钥。

## 4. 自查后交付

先运行 `shop.py check "<网页文件夹>"`，再按 [references/acceptance.md](references/acceptance.md) 做实际验收。程序检查不代替看图。至少包含：桌面1440×900与手机390×844首屏、BGM、日历、问答、愿望；3D/备用电脑同步与点详情；所有代表商品短名+图对照；日历跨年搜索；愿望打卡、修改、刷新后可见恢复；控制台和全页/所有详情弹窗隐私检查。

单文件复制到**没有 images 目录**的新目录、换个名字重新打开；确认每张引用图片均已内嵌，不残留本地文件路径。单文件内嵌全部图片，可能有几十 MB，打开后看一眼首屏和几张图就够，不要等页面“全部加载完”。自查的任何一步等了 2 分钟还没结果，就放弃这一步，写成“未测”，继续往下交付，不要一直等。新装机器和真实浏览器没测到就写“未测”。不要把生成/请求成功当作验收通过。

最后交付：完整网页文件夹、单文件、截图、商品图对照、覆盖报告、简短说明。说明展示多少单/多少商品行、筛掉什么、个性化在哪里、事实或版权待确认处，以及实际测过的环境。不给消费总额排名，不写未经验证的“首次/最多/唯一”。

所有内容先本地交付。分享或公开会暴露商品与购买记录，必须等用户明确同意后再生成公开链接。
